# AppWatch（アプリ見守当番）仕様書

2026-10-31

## 1. 概要

スマートフォンに慣れていない人の端末で、インストール済みのアプリを定期的に記録し、不要なアプリを本人がすぐに削除できるようにするAndroidアプリ。端末1台で完結して動く。家族などの手助けする人（以下「管理者」）は、対面で設定を行い、別の端末で記録を閲覧できる。

- **本人**：トップ画面で「確認が必要なアプリ」を見て、不要なら削除する。ホーム画面のウィジェットで状態を確認する。
- **管理者**：歯車アイコンの長押しで開く設定から、アプリごとの確認状態・注意アプリの事前登録・履歴の比較を行う。書き出したデータを別の端末に取り込んで閲覧する。
- **アプリは1種類**。本人用・管理者用の区別はなく、どの端末でも同じAPKを使う。
- **端末間の自動の通信は行わない**。データの受け渡しは、利用者が手で行うファイルの書き出しと取り込みだけとする。

### 前提と制約

- インストールそのものは止められない。新しいアプリは次のチェックで検出する。
- 削除は毎回、Android の確認画面を通る。無効化はアプリから行えないため、Android のアプリ情報画面へ案内する。
- チェック間隔より短い時間で入れて消されたアプリは検出できない。
- 本アプリが Android の設定やホーム画面から直接削除された場合は、警告を出せない。
- 本アプリが Android の設定から強制停止された場合、次に本アプリを開くまで定期チェックとウィジェットの更新が止まる。ウィジェットは止まる前の表示のままになり、「チェックが停止しています」は表示できない。

## 2. 動作環境と権限

### 対応 OS

- minSdk 26（Android 8.0）以上。targetSdk・compileSdk は作成時点の最新の安定版。
- Google Play 開発者サービスは不要。
- 仕事用プロファイルや2人目のユーザーのアプリは対象外。

### 権限

| 権限 | 用途 |
| --- | --- |
| QUERY_ALL_PACKAGES | 全アプリの一覧取得（Android 11 以降で必要） |
| REQUEST_DELETE_PACKAGES | 削除の依頼（Android の確認画面あり） |
| REQUEST_IGNORE_BATTERY_OPTIMIZATIONS | 電池の最適化から外す依頼 |

- インターネット接続と通知の権限は持たない。お知らせはウィジェットで行う。

### Android のバージョンによる違い

| 項目 | Android 11 以上 | Android 8〜10 |
| --- | --- | --- |
| 入手元の判定 | `getInstallSourceInfo` を使う | `getInstallerPackageName` を使う。入手のきっかけになったアプリは分からない |
| 署名の情報の取得 | 新しい取得方法 | Android 8.x のみ取得方法が異なる |
| テーマ「システムに従う」 | 端末のダークモードに従う | 端末にダークモード設定がない場合はライト |
| 権限「未使用アプリの一時停止から除外」 | 表示する | 仕組みがないため表示しない |

### 使用する部品

Android Studio の新規プロジェクトに標準で含まれるもの（Jetpack Compose、Material 3 など）以外に、次を使う。外部（Google 以外）の部品は使わない。

| 部品 | 用途 |
| --- | --- |
| Room | 記録・確認状態などのデータベース |
| DataStore | 設定値の保存 |
| WorkManager | 定期チェック |
| Glance | ホーム画面ウィジェット |
| AppCompat | アプリ内の言語切り替え（Android 8〜12 対応のため） |
| KSP（ビルド用） | Room のデータベース定義の生成。ビルド時だけ使い、アプリには含まれない |

テスト専用の部品（アプリには含まれないもの）は、kotlinx-coroutines-test の使用を認める。

## 3. 使い方

端末ごとの使い方の区別はない。どの端末も、初回設定のあと自分のアプリを定期的に記録し、削除を手伝う（見守る）。書き出したデータを取り込めば、他の端末のデータも閲覧できる（第7章）。

- 本人の端末：本人がトップ画面とウィジェットで状態を確かめ、不要なアプリを削除する。
- 管理者の端末：管理者の端末も同じく自分のアプリを見守る。本人の端末から書き出したデータを取り込んで閲覧する。

## 4. アプリの分類と判定

各アプリは「種類」「入手元」「警告」「確認状態」「端末上の有無」で扱う。前の3つは自動で判定し、確認状態は管理者が設定する。

### 種類

| 種類 | 判定 |
| --- | --- |
| 後から導入 | システムアプリの印がない |
| プリインストール | システムアプリの印があり、ホーム画面のアイコンがある（更新済みのものを含む） |
| システム | システムアプリの印があり、ホーム画面のアイコンがない |

### 入手元

| 入手元 | 判定 |
| --- | --- |
| Google Play | インストールしたアプリが Google Play ストア |
| Google Play 以外 | インストールしたアプリが Google Play ストア以外 |
| 入手元が分からない | インストールしたアプリが取得できない |

### 警告

自動で判定し、該当するアプリはトップ画面で目立たせる（理由は色付きの札で出す。第6章「確認が必要になった理由の札」）。

- 入手元にかかわる警告（Google Play 以外から入った・入手元が分からない）は、「後から導入」のアプリにだけ付ける（プリインストールとシステムは入手元が取れないのが普通のため）。
- 開発用の署名・署名が変わった・再インストールは、種類で区別しない（プリインストールとシステムのアプリにも、後から導入と同じ基準で付ける）。

警告の種類：

- Google Play 以外から入った
- 入手元が分からない
- 開発用の署名のアプリ
- 署名が変わった（同じパッケージ名で別の作り手のアプリに入れ替わった可能性）
- 以前に削除したアプリが再インストールされた

### 確認状態

| 確認状態 | 印 | 意味 |
| --- | --- | --- |
| 未確認 | 灰色の点線の丸に「?」 | 初期状態。まだ確認していない |
| 問題なし | 緑の丸に「✓」 | 確認して、残してよいアプリ |
| 要注意 | 赤の丸に「!」 | 削除してほしいアプリ。トップ画面で最上位に赤枠で表示 |

- 確認状態はパッケージ名で保存し、削除後も残す。再インストールされると以前の確認状態で表示する。
- 署名が変わったアプリは「問題なし」を「未確認」に戻し、理由を表示する。
- 「以前に削除したアプリ」「署名が変わった」の警告は、確認状態を「問題なし」にした時点で消す。変化の記録は「これまでの経緯」に残る。
- 「問題なし」のままのアプリに警告が付いた場合（「問題なし」のまま削除・再インストールされたときなど）は、管理者用の詳細で改めて「問題なし」を保存すると警告を消す。
- アップデート（バージョンの変更）では確認状態を変えない。
- 警告のあるアプリは、一括操作で「問題なし」にしない（1件ずつ確認する）。

### 本アプリ自身

- 他のアプリと同じく一覧に表示し、判定も同じに行う。名前の横に「本アプリ」のラベルを付ける。
- 本アプリ自身には、警告の札（入手元が分からない、Google Play 以外、開発用の署名など）を出さない。トップ・アプリの詳細（本人用・管理者用）・確認状態の画面・削除の確認のダイアログのどこでも同じ。「確認が必要なアプリです」の見出しも出さず、「本アプリ」のラベルだけを出す。警告の判定と記録はほかのアプリと同じに行い（表示だけを変える）、確認状態の画面の絞り込み（警告・入手）にも判定どおりに当てはめる。
- アプリ内から本アプリを削除するときは、削除の確認のダイアログの中に警告を出す（第6章「削除の確認」）。

## 5. 定期チェックと記録

### 定期チェック

- WorkManager の周期ジョブで全アプリを取得し、前回の状態との差を変化として記録する。
- 間隔：30分／1時間／3時間／6時間／12時間／24時間。初期値は12時間。正確な時刻は求めない。
- 同じ処理を一意のジョブとして登録し、二重に動かない。実行中は排他制御を行い、直前1分以内にチェック済みなら省略する。
- アプリを開いたとき、ウィジェットをタップしたときにも1回チェックする。
- チェックのあとウィジェットを更新する。ウィジェット自体の定期更新（30分）は予備とする。

### 記録の形

- 最初のチェックの全件を「基準」として保存し、以後は変化（イベント）だけを追記する。
- 任意の日時の状態は、基準にその日時までの変化を当てはめて求める。2つの日時を求めて差を取ることで、履歴と比較を行う。
- チェックの実行記録は日ごとにまとめる（日付、回数、最後の時刻）。「変化なし（チェック n回）」の表示と、停止の判定に使う。

### 変化の種類

| 種類 | 内容 |
| --- | --- |
| 追加 | 新しく検出（再インストールも含む） |
| 削除 | 検出されなくなった |
| 更新 | バージョンが変わった |
| 有効化・無効化 | 有効・無効が切り替わった |
| 署名が変わった | 別の作り手のアプリに入れ替わった可能性 |
| 初期化 | 端末の初期化・機種変更後の復元で、基準を取り直した |

## 6. 画面

文言は大人向けに漢字を使う（「下さい」「経過」「起動」「停止」など）。目安は常用漢字の範囲で、新聞や役所の文書で普通に漢字で書く語は漢字にする（「普通」「分かる」「恐れ」「既に」など）。形式的な語（「〜こと」「〜もの」「〜ため」「〜ところ」）、補助的な語（「ある」「いる」「なる」「〜てほしい」）、慣用でひらがなが普通の語（「お知らせ」「おすすめ」）、常用漢字にない字はひらがなにする。本人向けの画面（トップ・本人用の詳細・ウィジェット・削除の確認・注意の説明・動作チェック）はやさしく短く、管理者向けは説明の文にする。です・ます調にそろえ、お願いは「〜して下さい」の形にする。かっこは「」（その中の引用は『』）、数字と英字は半角にする。アプリ名・取り込んだデータの端末の名前を文に入れる時は「」で囲み、前後に空白を入れない。同じ文の中の状態名は『』で囲む（例：「Chrome」を削除しますか？、「家計メモ」を『要注意』にしました）。英語は今の書き方（アプリ名を囲まない）。同じものは同じ言葉で呼ぶ（「削除」「管理者」「初回設定」など）。略語は避ける。フォントは全画面で共通。管理者用の画面は右上に「管理者用」の印を出す（黄色の背景に濃い文字。ライト・ダークとも同じ。すべての管理者用の画面で同じ部品を使う）。

### 日付の表示

- 画面に出す日付（トップ・アプリの詳細・これまでの経緯・確認状態の画面・事前登録の一覧の登録した日・取り込んだデータの「時点・取り込み」・履歴と比較の一覧の行・動作チェックの最終チェック）には、曜日と「何日前」を添える。例：「11月8日(土) 21:16 にインストール ・ 2日前」「11/8(土) 21:16 ・ 2日前」。英語は「Sat, Nov 8, 21:16 · 2 days ago」。
- 何日前は青の太字。時刻ではなく端末の時間帯の暦の日で数え、同じ日は「今日」、前の日は「昨日」、それより前は「n日前」（英語は today／yesterday／n days ago）。今と違う年は年も出し、時刻は出さない（例：2025/9/3(水) ・ 433日前）。
- 曜日・月名は言語の設定から作る。「何日前」は途中で折り返さない。
- 曜日・何日前を付けないもの：履歴と比較の期間の選択（比較元／比較先）、共有の文字、書き出しファイルの中・ファイル名、最近の書き出しの一覧。ウィジェットの「最終チェック」は幅が狭いので曜日だけを足す。

### 画面の一覧

| 画面 | 使う人 | 開き方 |
| --- | --- | --- |
| トップ | 本人 | アプリ起動、ウィジェット |
| アプリの詳細（本人） | 本人 | トップのカード・一覧の行、「詳しく」 |
| 削除の確認 | 本人・管理者 | トップ・アプリの詳細の「削除する」「削除」 |
| 設定メニュー | 管理者 | トップの歯車アイコンを長押し |
| アプリの確認状態 | 管理者 | 設定メニュー |
| アプリの詳細（管理者） | 管理者 | 確認状態・履歴と比較の行 |
| 注意アプリの事前登録 | 管理者 | 設定メニュー、確認状態、Google Play からの共有 |
| 履歴と比較 | 管理者 | 設定メニュー |
| データの書き出し・取り込み | 管理者 | 設定メニュー |
| 取り込んだデータ | 管理者 | 設定メニュー、ファイルを開いたときの取り込みの後 |
| 初回設定 | 管理者 | 初回起動時 |
| 注意の説明 | 本人・管理者 | アプリの詳細の警告の欄、トップの札 |
| 動作チェック | 本人・管理者 | トップの動作チェックのボタン、設定メニュー |

### トップ（本人）

- 上部に検索の窓（アプリ名・パッケージ名の部分一致、大文字・小文字を区別しない、消すボタン付き）。確認状態の画面と同じ部品を使う。検索はトップのすべての一覧（新しく入ったアプリ・まだ確認していないアプリ・すべて）に効き、当てはまるアプリがなければ「当てはまるアプリはありません」を出す。検索の文字は保存しない（画面を離れたら空に戻す）。
- 検索の下の切り替え：「確認が必要なアプリ」（初期）／「すべて」。
- 「新しく入ったアプリ」を大きなカードで表示。新しく入ったアプリは「最初のチェックより後に追加され、確認状態が『問題なし』になっていないアプリ」とする。要注意のアプリと、署名が変わって「未確認」に戻ったアプリは、新しいかどうかに関係なくカードで表示する（署名が変わったアプリはオレンジ枠、「問題なし」になるまで）。並びは要注意 → 警告あり → その他。
  - 要注意：赤枠。管理者メモを表示。
  - 警告あり：オレンジ枠。
  - 確認が必要になった理由（要注意、以前に削除したアプリ、署名が変わった、開発用の署名、Google Play 以外から入った、入手元が分からない）は、普通の説明の文と分けて札で出す（後述）。入手元の札を出すときは、説明の文に入手元を重ねて書かない。
  - 各カード（要注意を含む）に「削除する」と「詳しく」。
  - システムのアプリには削除ボタンを出さない。
- 「まだ確認していないアプリ」の一覧と「削除」ボタン。一覧の行にも理由の札を出す（「問題なし」のアプリには出さない）。
- カード・一覧の行（どのタブでも）を押すと、アプリの詳細（本人）を開く。「詳しく」も同じ画面を開く。
- 「削除する」「削除」を押すと、削除の確認（後述）を出してから Android の削除の確認に進み、削除の後に結果を表示する。
- 右上の歯車は薄い色で、長押しのときだけ反応する。
- 歯車の左に動作チェックのボタン（盾にチェックの形）を置き、押すだけで動作チェックの画面を開く（歯車の長押しとは別）。動作チェックが「確認が必要」のときは、ボタンの右上に小さなオレンジの点を付ける。読み上げは「動作チェック」。
- カード・一覧の札を押すと、注意の説明（後述）を開く。

### アプリの詳細

本人用と管理者用で同じ画面（同じ部品・同じ並び）を使い、文字の大きさもそろえる。

- 上から：アプリ名（本アプリならラベル）／バージョン／入手元・インストール日／パッケージ名
- 警告の欄、確認の状態、管理者メモ、これまでの経緯
- 警告の欄は、理由をトップと同じ札で出し、再インストール・署名の変更は日付の説明を添える。本アプリ自身には警告の欄を出さない（第4章）。
- 警告の欄の見出しの右に「説明 ›」を出し、欄のどこを押しても注意の説明（後述）を開く（本人用・管理者用とも）。
- 上部のインストール日とこれまでの経緯の各行には、曜日と何日前を添える。
- 本人用（トップから開く）：確認状態・管理者メモは見るだけ（押しても変わらない。「（管理者が設定）」を添える）。「保存」は出さない。下部は「Android のアプリ情報」と「削除する」だけで、「削除する」は後から導入のアプリだけに出す。「管理者用」の印は出さない。管理者メモは本人にも見せる。
- 本人用の右上に、トップと同じ設定の歯車を置く（本アプリ自身の詳細でも同じ）。動きもトップの歯車と同じで、長押しでそのアプリの管理者用の詳細（この端末のデータ）を開き、短く押しても何も起きない。読み上げもトップと同じ。管理者用の詳細で保存して戻ると本人用の詳細に戻り、変わった確認状態・管理者メモがすぐに出て、「元に戻す」付きのお知らせを本人用の詳細で出す。保存しないで戻る時の確認は管理者用と同じ。
- 管理者用：確認状態と管理者メモを編集できる。「保存」「Android のアプリ情報」「削除する」。
- 「削除する」は、削除の確認（後述）を出してから Android の削除の確認に進み、削除の後に結果を表示する。本人用で削除したときは、チェックで端末から消えたのが分かった時点でトップに戻る。
  - 「保存」で前の画面に戻り、「元に戻す」付きのお知らせを出す。保存しないで戻るときは確認を出す。

### 削除の確認

削除するときは、本アプリの確認のダイアログを出してから Android の削除の確認に進む（Android の確認は省けない）。削除の後に結果を表示する。トップ・アプリの詳細（本人用・管理者用）のどこから削除しても同じ形にする。

- 上から：アプリのアイコン、アプリ名、バージョン、大きな文字で「『〇〇』を削除しますか？」（画面ではアプリ名を「」で囲む）、「次に Android の確認が出ます。『OK』を押すと削除されます。」
- 警告のあるアプリは、トップ・アプリの詳細と同じ理由の札（後述）を添える。
- 本アプリ自身のときは、札の代わりに「このアプリを削除すると、見守りが止まり、これまでの記録も消えます。削除する前に管理者に相談して下さい。」を同じダイアログの中に出す（ダイアログを重ねない）。
- 「やめる」（目立つボタン）と「削除する」（赤の枠）。「削除する」の後、Android の削除の確認に進む。

### 注意の説明

下から出る画面（ボトムシート）。アプリの詳細の警告の欄、トップの札から開く。本アプリ自身は警告の欄・札がないので、説明もない。

- 見出し「『〇〇』が確認の対象になった理由」（画面ではアプリ名を「」で囲む）、リード「チェックの付いたものが、このアプリに当てはまります。心当たりがなければ、管理者に相談して下さい。」、6つの注意、下に「閉じる」（青・大）。
- 6つの注意はいつも同じ順（Google Play 以外から入った → 入手元が分からない → 開発用の署名 → 署名が変わった → 以前に削除したアプリ → 要注意（管理者が設定））。当てはまるもの（札に出している理由）だけにチェック（丸の中のチェック）と色（警告はオレンジ系、要注意は赤系）を付け、当てはまらないものは灰色にする。チェックの有無は読み上げでも分かるようにする。
- 入りきらないときは注意の一覧をスクロールする（「閉じる」はいつも見える）。
- 文：
  - Google Play 以外から入った：Google Play ストア以外（ウェブサイト・送られてきたファイルなど）から入れたアプリです。
  - 入手元が分からない：どこから入れたのか、スマートフォンに記録が残っていないアプリです。
  - 開発用の署名：アプリを作る人が試すための作り方のアプリです。普通に配られているアプリには、まずありません。
  - 署名が変わった：名前は同じでも、作った人の印が前と変わりました。別の人が作ったアプリに入れ替わった恐れがあります。
  - 以前に削除したアプリ：一度削除したアプリが、また入っています。自分で入れ直していなければ注意して下さい。
  - 要注意（管理者が設定）：管理者が「注意が必要」と決めたアプリです。削除をおすすめします。
- 英語も同じ内容で、平易な文にする。

### 確認が必要になった理由の札

トップのカード・一覧、アプリの詳細の警告の欄、確認状態の画面の行、削除の確認のダイアログで、同じ部品・同じ見た目の札を使う。本アプリ自身には警告の札を出さない（第4章）。

- 札の文字：要注意／以前に削除したアプリ／署名が変わった／開発用の署名／Google Play 以外から入った／入手元が分からない。色だけに頼らず、札の文字で理由が分かるようにする。
- 色：警告はオレンジ系、要注意は赤系の背景に、読める濃さの文字。ライト・ダークの両方で読めること。
- 並び（優先の順）：要注意 → 以前に削除したアプリ → 署名が変わった → 開発用の署名 → Google Play 以外から入った → 入手元が分からない。
- 確認状態の画面の行では、確認状態は印で示すので「要注意」の札は出さない。再インストール・署名の変更は、札のすぐ後に見つけた日を出す。

### アプリの確認状態（管理者）

- 上部：データの切り替え（この端末／取り込んだデータ）、検索（アプリ名・パッケージ名。幅の都合で案内の文は「検索」だけ、読み上げは「アプリ名・パッケージ名」）、「絞り込み」ボタン、「事前登録」ボタン（幅の都合で「＋」だけ。読み上げは「事前登録」）。

- 絞り込みは、親子の関係があるツリー。確認状態はツリーの外で、すべてのアプリに効く。

```
確認状態：未確認／要注意／問題なし
導入済
  状態：有効／無効
  警告：なし／開発用の署名／署名が変わった／再インストール（1つのアプリに複数付くことがある）
  種類：
    後から導入
      入手：Google Play／Google Play 以外／入手元が分からない
    プリインストール
    システム
未導入
  削除したアプリ
  事前登録だけ
```

- アプリは、ツリーの自分の位置までの道のりにある項目がすべてオンなら表示する。同じ組（確認状態・状態・警告・入手）の中は、自分の値がオンなら当たる。
  - 導入済のアプリ：「導入済」がオン、かつ「状態」で自分の値がオン、かつ「警告」で自分の警告（なければ「なし」）のどれかがオン（警告が複数あれば、どれか1つがオンなら表示）、かつ自分の種類がオン。後から導入のアプリは、さらに「入手」で自分の値がオン。
  - 「警告」は導入済のアプリ全部（後から導入・プリインストール・システム）に効く。「入手」は後から導入のアプリだけに効く。
  - 未導入のアプリ：「未導入」がオン、かつ「削除したアプリ」か「事前登録だけ」の自分の方がオン。状態・警告・種類・入手は効かない。事前登録だけで一度も入っていないアプリが「事前登録だけ」、それ以外（削除したアプリを事前登録したものを含む）は「削除したアプリ」。

### ウィジェット（4×1、縦に4×2まで広げられる、本人）

優先度の高い順に1つを表示する。下部に「最終チェック」を表示する。タップでアプリを開き、チェックしてウィジェットを更新する。

標準の大きさは 4×1 で、縦に 4×2 まで広げられる（横は4のまま）。高さに合わせて2つの形を使い分ける。

- 枠：状態の色の角丸の縁（2.5dp）。左上に「アプリ見守当番」（英語は「AppWatch」）の札を、縁の上に重ねて出す（4×1・4×2 とも）。札の文字は縁と同じ色の 12sp の太字で、札は縁と同じ色・同じ太さの縁取りの角丸、中はウィジェットの中と同じ色。札の縦の真ん中が縁の線に来るようにし（左から 14dp）、そのため縁の外側の上に 12dp の余白（透明）を取る。

- 低い形（4×1）：左に状態の印（色付きの丸のアイコン）、右に見出し1行（下の表の「低い形の見出し」）と、その下に小さく「最終チェック」の1行。補足の文は出さない。幅の狭いホーム画面では、見出しの文字を少し小さくする。
- 高い形（4×2）：見出し（2行まで）、補足の文、「最終チェック」。
- 既に 4×2 で置いてあるウィジェットは、その大きさのまま高い形で表示する。

| 順 | 見出し | 低い形の見出し | 補足（高い形だけ） | 色 | 印 |
| --- | --- | --- | --- | --- | --- |
| 1 | 要注意のアプリ n件 | 要注意のアプリ n件 | 削除しない場合は、管理者に相談して下さい | 赤 | ! |
| 2 | チェックが停止しています | チェックが停止中 | アプリを開いても直らない時は、管理者に連絡して下さい | 灰 | ‖（一時停止） |
| 3 | 確認が必要なアプリ n件 | 確認が必要なアプリ n件 | 削除しない場合は、管理者に確認を依頼して下さい | オレンジ | ? |
| 4 | 設定の確認が必要です | 設定の確認が必要 | 管理者に設定の確認を依頼して下さい | オレンジ | 歯車 |
| 5 | 管理者に初回設定を依頼して下さい | 初回設定が必要です | 初回設定が完了していません | 青 | i |
| 6 | 確認が必要なアプリは0件 | 確認が必要なアプリなし | このままお使い下さい | 緑 | ✓ |

- 「停止」は、最終チェックがチェック間隔の3倍より前のとき。
- 初回設定が終わる前は、他の状態より優先して5を表示する（チェックを行わないため、他の状態は判定できない）。
- 見出しが2行になる場合は、言葉の途中で改行しない。
- ウィジェットの一覧には見本の画像（低い形）を表示する。
- ウィジェットのテーマは端末の設定に従う。言語はアプリで選んだ言語に従う（Android 12 以下も）。

### 初回設定

次の3画面。

初回設定が終わるまでは、アプリを開いたときのチェックと定期チェックを行わない。最初のチェックは2の画面で行う。

1. **見守りを続けるための設定**：上に「アプリ見守当番へようこそ」の見出しと短い説明を出す。電池の最適化からの除外、未使用アプリの一時停止からの除外（Android 11 以上）。アプリ一覧の取得と削除の権限はインストール時に許可されている旨を表示。「後で設定する」も可。未使用アプリの一時停止は、開いた画面のどのスイッチを切り替えるかを案内する（Android 12 以上と 11 で名前が違う）。
2. **最初のチェック**：記録した件数を表示し、3つの確認状態の意味を説明する。次の項目ごとに件数を表示し、チェックを付けた項目のアプリをまとめて「問題なし」にする（警告のあるアプリは除く。ただし「このアプリ」の行の本アプリ自身は、警告があっても対象に含める）。変えるのは「未確認」のアプリだけで、「要注意」のアプリはそのままにする。本アプリ自身は「このアプリ」の行だけで数える。

   | 項目 | 説明 | 初期 |
   | --- | --- | --- |
   | システム | Android の動作に必要な組み込みアプリ | チェックあり |
   | プリインストール | 端末の購入時から初期導入されているアプリ | チェックあり |
   | Google Play | 後から導入・Google Play から入手 | チェックあり |
   | Google Play 以外 | 後から導入・Google Play 以外から入手 | なし |
   | 入手元が分からない | 後から導入・入手元が分からない | なし |
   | このアプリ（アプリ見守当番） | 本アプリ自身 | チェックあり |

3. **ウィジェットの追加**：ボタン1つでホーム画面に追加する（4×1。縦に広げられる）。ホーム画面が追加に対応していない場合は、置き方を文字で案内する。

アプリを開くたびに1の状態を確認し、外れていればウィジェットに「設定の確認が必要です」を表示する。設定メニューの「動作チェック」で、各設定の状態、最終チェック日時、直近7日のチェック回数を確認できる。

## 7. データの書き出しと取り込み（閲覧）

### 書き出し

- この端末の記録・確認状態・設定をまとめた `.appwatch` ファイルを作る。
- 保存は「ファイルとして保存」で、保存場所は利用者が選ぶ。
- ファイルは暗号化されない。端末同士の受け渡しは、対面での近距離共有や、本人と管理者だけが使う保存場所を使うことを推奨する。
- ファイルの中身は、形式の名前と版、書き出し日時、端末の情報（識別番号・機種・OS・アプリのバージョン）、この端末の記録（基準・最新の状態・変化・管理者の設定・チェックの実行記録）、設定（チェック間隔・テーマ）。JSON を gzip で圧縮して保存する。ファイル名は `appwatch_YYYYMMDD_HHMM.appwatch`。
- 取り込んだデータは書き出さない。
- 「最近の書き出し」に、直近の書き出し（日時・ファイル名・大きさ）を表示する。

### 取り込み

ファイルを開くと、次のどちらかを選ぶ。

| 選択 | 内容 |
| --- | --- |
| 閲覧のみ | 「取り込んだデータ」として追加する。同じ端末のデータは上書きする。閲覧中は「閲覧中：『端末名』（日時 時点）」を表示し、確認状態の変更などの操作はできない |
| この端末に復元 | この端末のデータをファイルの内容で置き換える（確認画面あり） |

- 取り込んだデータごとに端末名を付けられる。確認状態・履歴と比較・アプリの詳細で、データを切り替えて閲覧する。
- 取り込んだデータは設定メニューから削除できる。
- 新しすぎる形式のファイルは取り込まず、アプリの更新を案内する。古い形式は変換して取り込む。
- ファイルは「書き出し・取り込み」の画面から選ぶほか、ファイルアプリなどから開くこともできる。AppWatch のファイルでなければ、その旨を表示する。
- 取り込みの前に、機種・OS・書き出し日時・アプリの件数・要注意の件数を表示する。端末の名前の初期値は、同じ端末のデータがあればその名前、なければ機種名。
- 同じ端末かどうかは、ファイルの端末の識別番号で判断する。この端末自身のファイルは「閲覧のみ」では取り込まない（復元は選べる）。
- 選択中のデータは設定値として保存する。データの切り替えは、取り込んだデータがあるときだけ表示する。
- 閲覧中は、確認状態の画面の選択・まとめての変更・事前登録、アプリの詳細の保存・アプリ情報・削除を出さず、「閲覧中のデータは変更できません」を表示する。
- 取り込んだデータの履歴と比較では、「今日」の代わりにファイルの書き出し日を使う。「前回以降」は、同じ端末の前回取り込んだファイルの書き出し日から、今回の書き出し日までとする。

### 復元

- 復元時に「端末を初期化（または機種変更）しましたか？」を確認する。
  - **はい**：確認状態と経緯は引き継ぎ、今の端末のアプリを新しい基準にする。履歴に「初期化」を1件記録し、新しく見つかったプリインストールとシステムのアプリ（ファイルの最新の状態になく、確認状態もないもの）をまとめて「問題なし」にするか尋ねる。
  - **いいえ**：データをそのまま戻し、次のチェックで差を記録する。
- 端末を識別する番号は、ファイルのものを引き継ぐ。
- 復元すると、ファイルの設定（チェック間隔・テーマ）も戻し、定期チェックを登録し直す。取り込んだデータはそのまま残す。

## 8. データモデル

すべての表に「データの番号」を持たせ、この端末のデータと取り込んだデータを1つのデータベースに並べて持つ。定期チェックが書き込むのはこの端末のデータだけ。

### Room

| 表 | 主な項目 | 役割 |
| --- | --- | --- |
| dataset | 番号、名前、種類（この端末／取り込み）、端末の識別番号、機種、OS、アプリのバージョン、書き出し日時、前回の書き出し日時、取り込み日時 | データのまとまり。この端末の番号は初回起動時に作り、端末の識別番号を兼ねる。取り込んだデータは自分の番号を持ち、書き出した端末の識別番号を別に持つ |
| baseline_app | データの番号、パッケージ名、取得日時、各アプリの状態 | 基準（初期化時に取り直す） |
| app_current | データの番号、パッケージ名、名前、バージョン、種類、入手元、有効・無効、警告の情報、インストール日時、端末上の有無 | 最新の状態 |
| app_event | データの番号、日時、種類、パッケージ名、名前、詳細 | 変化の記録（追記のみ） |
| app_policy | データの番号、パッケージ名、確認状態、管理者メモ、事前登録の有無、仮のアプリ名、更新日時 | 管理者の設定。削除後も残す |
| scan_daily | データの番号、日付、回数、最後の時刻 | チェックの実行記録（日ごと） |

### DataStore（設定値）

チェック間隔、テーマ、確認状態の画面の絞り込み、選択中のデータ、初回設定の完了状態。

前の版で保存した「使い方」（見守る端末／閲覧専用）の値は使わない。閲覧専用だった端末は、更新後に初回設定が未完了の扱いになり、初回設定から始める（この端末の記録・取り込んだデータは消さない）。この値は初回設定を終えたときに消す。

言語は Android のアプリ別言語の仕組み（AppCompat）が保存するため、DataStore には持たない。書き出しファイルにも含めない。

### 元に戻す

確認状態の変更は、変更前の値を持つ変化として記録する。「元に戻す」は直前の操作（一括操作はまとめて1回）を取り消す。取り消しも変化として記録する。元に戻せるのはお知らせが出ている間だけとする。

## 9. バックアップ

- Android の自動バックアップ（Google のバックアップ）を有効にし、データベースと設定値を対象にする。
- 再インストール時に自動で戻る。最後のバックアップ以降の変更（おおむね1日分）は失われる。
- 手動の書き出しファイル（第7章）も、機種変更時のバックアップとして使える。

## 10. 開発の進め方

| 段階 | 内容 |
| --- | --- |
| 1 | 定期チェック、記録、分類・警告の判定、トップ、アプリの詳細、削除（削除の確認を含む）、ウィジェット、初回設定 |
| 2 | 設定メニュー、確認状態、事前登録、履歴と比較、テーマ・言語・権限・情報 |
| 3 | データの書き出し・取り込み（閲覧・復元）、データの切り替え |

データの形（データの番号、書き出しファイル）は最初から最終形で作る。

## 11. 対象外

- 管理者からの遠隔の指示、管理者への自動・メールでの送信
- 端末間の自動同期、インターネット通信
- 通知

## 12. 確認が必要な事項

- 正式版を Google Play 以外（ファイルアプリなど）から入れたときの入手元の判定結果
- メーカー独自の省電力機能による定期チェックの停止の有無（対象の端末で確認）
- 取り込んだデータの閲覧中の操作を記録として残す方法（検討中）
